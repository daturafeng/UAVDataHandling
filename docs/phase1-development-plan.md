# Phase 1 Development Plan

## 1. 背景

本项目用于处理无人机拍摄图像。首个核心需求是：

- 输入图像中的像素坐标 `(u, v)`。
- 从图片中读取无人机状态，或允许外部传入状态参数。
- 输出该像素点对应的 `WGS84` 经纬度坐标。

当前阶段目标是先搭建“单点坐标解算”的最小可验证闭环，不同时引入过多扩展能力。

## 2. 已确认测试数据资源

当前已确认可直接用于首阶段开发和验证的真实数据位于：

- `G:\DJIImage\drone_images`

已确认的文件构成：

- `85` 张 `DJI_*.jpeg`
- `2` 个 `*.jpeg.aux.xml`
- `1` 个 `*.MRK`
- `1` 个 `*.NAV`
- `1` 个 `*.OBS`
- `1` 个 `*.RTK`

当前抽样确认结果：

- JPEG 分辨率样例为 `4032 x 3024`
- JPEG 内嵌了 DJI 的 `XMP` 元数据
- `XMP` 中已存在 `drone-dji:*` 字段，可直接读取无人机位置、姿态和 RTK 状态
- `*.jpeg.aux.xml` 中包含展开后的 `EXIF` 与 `XMP` 字段，适合做调试和交叉核验
- `*.MRK` 是可读文本，包含按曝光记录组织的经纬度、椭球高和质量信息
- `*.NAV` 和 `*.OBS` 为 RINEX 文件，可视作后续高精度扩展的 GNSS 参考数据
- `*.RTK` 当前看起来不是首阶段最直接的解析入口，可后续再专项处理

## 3. 首阶段目标

首版建议聚焦以下能力：

- 支持单张图像输入。
- 支持输入单个像素坐标。
- 支持从图像元数据中读取无人机状态。
- 支持外部传入状态参数并覆盖图像元数据。
- 输出该像素点对应的 `WGS84` 经纬度。
- 基于平地假设完成首版几何解算。

## 4. 暂不纳入范围

首阶段暂不默认纳入以下内容：

- DEM / DSM 地形修正
- 正射校正
- 图像拼接
- 多视图重建
- 亚米级高精度误差建模
- 批量处理工作流

## 5. 总体思路

建议先按“数据读取 -> 数据标准化 -> 几何解算 -> 坐标输出”的主链路开发。

### 5.1 输入层

输入建议支持：

- 图片路径
- 像素坐标 `(u, v)`
- 可选外部无人机状态参数
- 可选相机参数

### 5.2 元数据读取层

优先从图片中提取：

- 无人机经纬度
- 无人机高度
- 机体姿态 `yaw / pitch / roll`
- 云台姿态 `yaw / pitch / roll`
- 焦距
- 图像宽高
- 传感器尺寸
- 主点偏移

说明：

- 首版不要求所有字段都能从每张图片中完整读取。
- 如果图片缺少关键字段，则允许由外部参数补充。
- 如果关键字段仍然缺失，则返回明确错误，不静默输出结果。

已确认应优先适配的 DJI 字段包括：

- `drone-dji:GpsLatitude`
- `drone-dji:GpsLongitude`
- `drone-dji:AbsoluteAltitude`
- `drone-dji:RelativeAltitude`
- `drone-dji:GimbalRollDegree`
- `drone-dji:GimbalYawDegree`
- `drone-dji:GimbalPitchDegree`
- `drone-dji:FlightRollDegree`
- `drone-dji:FlightYawDegree`
- `drone-dji:FlightPitchDegree`
- `drone-dji:RtkStdLon`
- `drone-dji:RtkStdLat`
- `drone-dji:RtkStdHgt`
- `drone-dji:UTCAtExposure`

### 5.3 数据来源优先级

当同一字段来自多个来源时，首阶段建议采用如下优先级：

1. 外部显式传入参数
2. JPEG 内嵌 XMP 的 `drone-dji:*` 字段
3. `*.jpeg.aux.xml`
4. 基础 EXIF GPS 字段
5. `*.MRK` 中与曝光事件可匹配的字段

补充说明：

- 若多个来源冲突，应保留来源诊断信息。
- 若后续确认 `MRK` 与图像文件名、曝光时刻或序号存在稳定映射关系，可提升其优先级。

### 5.4 标准化层

不同来源的数据应统一转成内部模型，建议包含：

- `ImagePoint`
- `DronePose`
- `GimbalPose`
- `CameraIntrinsics`
- `GeoResult`

统一约定：

- 地理坐标使用 `WGS84`
- 局部计算使用 `ENU` 坐标系
- 距离单位使用米
- 经纬度使用十进制度数

### 5.5 几何解算层

首版建议采用如下解算链路：

1. 将像素坐标 `(u, v)` 转为相机坐标系中的视线方向。
2. 根据相机内参与主点位置建立像平面模型。
3. 结合云台姿态与机体姿态，将射线旋转到世界坐标系。
4. 令射线与地面平面相交，求出地面交点。
5. 将交点从局部 `ENU` 坐标转换为 `WGS84` 经纬度。

### 5.6 输出层

输出建议包含：

- `longitude`
- `latitude`
- 可选 `altitude`
- 可选诊断信息

诊断信息可包含：

- 是否使用图片元数据
- 是否使用外部覆盖参数
- 读取了哪些元数据来源
- 是否成功求得地面交点
- 中间姿态与内参摘要

## 6. 首版算法假设

为保证首版实现简单可验证，建议采用以下假设：

- 地面为单一平面
- 无人机位置已知
- 姿态角已知或可由图片读取
- 相机针孔模型足以支撑首版
- 暂不考虑镜头畸变，或先假设图像已近似校正

如果后续精度要求较高，再单独扩展：

- 畸变校正
- DEM 地形交会
- 更精细的相机标定参数

## 7. 首阶段如何使用这批 DJI 数据

建议把这批数据分三层使用：

### 7.1 主功能验证

直接使用 `DJI_*.jpeg`：

- 验证图像读取
- 验证 XMP / EXIF 提取
- 验证像素点到经纬度的完整流程

### 7.2 元数据解析验证

同时对照 `*.jpeg.aux.xml`：

- 核验字段名与字段值
- 辅助定位 JPEG 内嵌 XMP 的解析错误
- 验证高度、姿态和 RTK 标准差字段是否一致

### 7.3 后续高精度扩展准备

保留 `*.MRK`、`*.NAV`、`*.OBS`、`*.RTK` 的接入空间：

- `MRK` 可用于曝光事件对齐与 RTK 结果核验
- `NAV` / `OBS` 可为后续 GNSS 高精度分析预留基础
- `RTK` 可在后续确认格式后专项支持

## 8. 建议目录结构

建议后续按如下结构组织代码：

- `src/uav_geo/`
- `src/uav_geo/models/`
- `src/uav_geo/readers/`
- `src/uav_geo/geometry/`
- `src/uav_geo/services/`
- `tests/`
- `samples/`
- `docs/`

目录职责建议：

- `models`：定义数据模型
- `readers`：读取 EXIF/XMP/厂商元数据
- `geometry`：坐标系转换、姿态旋转、地面求交
- `services`：对外提供统一调用入口
- `tests`：单元测试与样例验证
- `samples`：样例图片与样例元数据
- `docs`：算法说明与设计文档

## 9. 技术选型建议

首版建议依赖：

- `numpy`：矩阵与向量运算
- `Pillow`：图像基础信息读取
- `exifread` 或 `piexif`：EXIF 读取
- `pyproj`：WGS84 与局部坐标转换
- `pytest`：测试框架

数据模型可选：

- `dataclasses`
- `pydantic`

建议优先保持实现简单，避免在首版引入过重框架。
